# [3.3] — Stable

3.3 is the largest AutoBangumi release in a while: a fully async backend architecture, aria2 promoted to a first-class download backend, movie/OVA/special support, per-bangumi release preferences, a hardened security stack, and a WebUI that updates over SSE instead of polling. REST API behavior is backward-compatible; existing databases upgrade automatically through schema v24.

## 3.3.6-beta.6 — mugosan/Auto_Bangumi_Fork: Reparse found 0 torrents for a bangumi with a stale DB link

- **Fixed: Reparse (added in beta.4) could resolve corrected metadata and compute the right new folder, but move 0 torrents and leave no new folder on disk.** It only looked up a bangumi's torrents via the `Torrent.bangumi_id` foreign key in the database — but a bangumi whose folder needs fixing in the first place is exactly the kind whose DB bookkeeping may be stale, so that lookup could come back empty even though the downloader was still tracking the torrents fine via its own `ab:<id>` tag (the same fallback `renamer.py` already relies on for this identical problem). Reparse now checks both. The response also now reports how many torrents were *found* versus moved/failed, so a future "0 moved" explains itself instead of looking like a silent no-op.

## 3.3.6-beta.5 — mugosan/Auto_Bangumi_Fork: fix a CI test flake from beta.4

- **Fixed: `test_client_has_keepalive_expiry` failed in GitHub Actions** (beta.4's CI run), a real bug locally masked by a `| tail` pipe that hid pytest's actual exit code. The shared httpx client (`module/network/request_url.py`) was cached at module scope with no awareness of which asyncio event loop created it; under pytest-asyncio's default one-loop-per-test-function behavior, a client left over from an earlier test's (now-closed) loop got handed to a later test and blew up with `RuntimeError: Event loop is closed` on close. Now tracks the loop a client was created on and discards/recreates it whenever the running loop no longer matches — not just a test-only fix, since the same failure mode could hit a real deployment if its event loop were ever recreated.

## 3.3.6-beta.4 — mugosan/Auto_Bangumi_Fork: consistent TMDB resolution, import any folder or torrent, a reparse/fix-folder action, and a real manual-import bug fix

- **Fixed: Mikan-sourced subscriptions (search or RSS) never got a year, TVDB id, or id_source** — only `tmdb`-sourced ones did (fixed in 3.3.6-beta.2), which meant the same "Search → pick → Subscribe" action behaved inconsistently depending on which site you searched. Mikan's homepage scrape is still the source of truth for title/poster (more reliable than a TMDB text search for those two), but year/tvdb_id/id_source are now filled in via the same TMDB cross-reference as everything else. Deliberately does not overwrite the season number derived from the release itself with TMDB's own guess, unlike the `tmdb` path — a likely contributor to separate season-mislabeling reports.
- **Fixed: the Search confirm screen showed no year/poster until *after* you hit Subscribe.** The beta.2 fix resolved metadata server-side at save time, but the confirm dialog itself still displayed the raw, unresolved search result beforehand — unlike Add RSS → Analyze, which resolves before showing anything. Picking a source/subtitle group now triggers the same TMDB/TVDB resolution immediately (a new `POST /rss/resolve` preview endpoint), so the confirm screen shows the real title/year/poster — for every provider, Mikan included — before Subscribe is even clickable.
- **Fixed a real bug in the 3.3.6-beta.2 manual-import feature: every route (`/candidates`, `/preview`, `/apply`, and the new `/upload`) returned an `AttributeError` on every real request.** The internal dataclasses are `@dataclass(slots=True)`, which have no `__dict__` — the API layer's `.__dict__` serialization crashed unconditionally. This was invisible to the shipped unit tests because they only exercised the manager-layer functions directly, never through FastAPI. Fixed with `dataclasses.asdict()`, and this release adds tests that go through the actual routes so this can't silently regress again.
- **New: manual import now accepts a plain folder path, not just a downloader-tracked torrent.** The "From a folder path" mode: point it at any path AutoBangumi's own process can see, and it's scanned recursively for media/subtitle files, then previewed and moved/renamed the same way, using plain filesystem operations instead of the downloader's API. Never overwrites an existing destination file, and never deletes/touches the source folder beyond moving files out of it.
- **New: manual import also accepts uploading a `.torrent` file directly.** A "Upload a .torrent file" mode adds the file straight to your downloader (untagged, same as adding it through the downloader's own UI), then walks into the same show-name/season → preview → confirm flow as everything else.
- **New: a "Reparse" action on the Edit Show screen for a bangumi whose folder is already wrong.** Re-runs the TMDB/TVDB parser against the stored title and, if the corrected title/year/id changes where the show should live, moves its already-downloaded torrents into the corrected folder. Deliberately never touches the season number (same reasoning as the Mikan fix above) or individual filenames — this fixes *which folder* the content lives in, not per-episode names.

## 3.3.6-beta.3 — mugosan/Auto_Bangumi_Fork: advance-mode filenames no longer carry the id tag

- **Fixed: "advance" rename mode was baking the `[tvdb-N]`/`[tmdb-N]` folder tag into every episode's filename** (e.g. `Title (2026) [tvdb-457532] S02E01.mp4` instead of `Title (2026) S02E01.mp4`). The tag is only meant to decorate the season folder for Plex/HAMA matching; the code that reverse-derives a show name from that folder for "advance" mode's filename template was copying the tag along with it. "pn" mode (the default) was never affected, since it names files from each release's own scraped title instead of the folder. Existing files already renamed this way aren't fixed automatically — they need a one-off rename to strip the tag back out.

## 3.3.6-beta.2 — mugosan/Auto_Bangumi_Fork: manual torrent import, a real subscribe-from-search bug

- **Fixed: subscribing from a Search result never got a year, TVDB/TMDB id, or poster resolution.** Search results are intentionally built without a full TMDB lookup (a keyword search can return dozens of rows across fansub groups, and resolving every one up front would be slow and wasteful — only title/poster get a lightweight patch for display). The follow-through was missing, though: picking a result and hitting Subscribe saved it exactly as-is, with no year/id ever filled in, permanently. Subscribing now resolves the full TMDB/TVDB metadata at that point, once, before the row is ever written. Subscribing via Add RSS → Analyze was never affected (that flow already resolves everything before Subscribe sees it).
- **New: manually import a torrent your downloader already has.** AutoBangumi only ever downloads through RSS subscriptions — a torrent added directly in qBittorrent's own UI (a manual DMHY/Nyaa search hit, a batch release your RSS filter excluded, etc.) never got organized. A new "Import a torrent" button on the Downloader page lists torrents AutoBangumi never tagged, and walks through show name/season → a preview of the exact rename+move (reusing the same TMDB/TVDB lookup and naming convention as everything else) → confirm. This is a one-off organize — no subscription or library entry is created, so it won't try to track future episodes.

## 3.3.6-beta.1 — mugosan/Auto_Bangumi_Fork: real TheTVDB ids, upstream 3.2.x history adopted

This fork was previously stuck on the 3.2.x line with its own divergent history; this release moves it onto upstream's 3.3.x line. Two things needed reconciling that don't affect anyone running unmodified upstream:

- **Schema-drift repair:** this fork had shipped its own schema_version 10/11 before this migration history existed, colliding with the real v10 (`preferred_group`/`preferred_resolution`) and v11 (`aria2_gid` table). A database that ran the fork's numbering is now detected automatically (via the `tvdb_id`-present/`preferred_group`-absent fingerprint) and repaired in place on next startup — no manual intervention needed, no data touched beyond the two backfilled columns and the `aria2_gid` table.
- **Real TheTVDB ids, without TheTVDB's API:** TheTVDB's own v4 API now requires a paid subscription for most usage, so this fork resolves the real TheTVDB series id via TMDB's own free `external_ids` cross-reference endpoint instead — no separate API key or subscription. Download folders are tagged `[tvdb-<id>]` when TMDB has that cross-reference, `[tmdb-<id>]` otherwise, and no tag at all when there's no match (previously always showed a bare `[tmdb-None]`). Nothing to configure — this is automatic for any `tmdb`-parsed subscription.

## 3.3.5 — Subscription, notification, and configuration fixes

3.3.5 is a bugfix release with five fixes across RSS subscriptions,
notifications, parsing, and configuration.

- **RSS re-subscribe (#1095):** re-subscribing a bangumi whose standalone RSS feed was disabled by the orphan-cleanup on deletion now re-enables the feed, so the rebuilt bangumi keeps updating.
- **Telegram notifications (#1094):** posters are now sent by their source URL (fetched server-side by Telegram), falling back to a local multipart upload and then to a plain text message. Completion notifications are no longer dropped when the poster send fails, and server rejections are logged with status and response body instead of as connection failures.
- **Parser (#1092):** the classic engine now matches the Preview admission policy for episode-less single releases that carry release evidence (group, resolution, source) but no special/movie marker — such as unmarked TV specials — admitting them as season-collect entries. Weak title-only strings remain rejected.
- **Reset all rules:** the bulk reset clears torrent records and aria2 mappings referencing bangumi before deleting the table, instead of rolling back with `FOREIGN KEY constraint failed`. Stale dedup records that made season-collect skip existing episodes are cleaned up with it.
- **Configuration:** unset passwords and API keys are no longer rendered as phantom `********` masks in the UI, and literal mask sentinels written into stored credentials by the 3.2.3/3.2.4 window (which masked without restoring) are scrubbed on load with a warning to re-enter the secret.

## 3.3.4 — Authentication, Parser Preview, and safe revision handling

3.3.4 is the stable consolidation of 3.3.4-beta.1 and beta.2. Classic remains
the default parser; Universal Parser Preview and automatic revision replacement
are both opt-in. Existing databases upgrade automatically through schema v24.

- **Authentication (#1074):** adds persistent multi-user sessions, first-run administrator bootstrap, user management, and scoped `api` / `mcp` tokens stored as hashes and revealed only once. Password changes, account disablement, and logout revoke the relevant sessions; browser refresh remains HttpOnly-cookie-only.
- **Universal Parser Preview:** adds a selectable parser for episodes, OVAs/specials, movies, ranges, and mixed collections. Classic remains the stable default, and the two engines never fall back to each other automatically.
- **Safe revision handling (#1078):** the default `hold` policy records and reports revision conflicts. Opt-in `replace` uses a recoverable stage-old → promote-new → clean-up-old flow for qBittorrent and aria2, only after strict identity and revision checks. Automatic replacement is limited to two single-file tasks; collections, incomplete identities, and multiple owners remain held.
- **Calendar (#1077):** archived anime no longer appear on the calendar.
- **Parser fixes (#1072/#1075):** versioned episodes such as `06v2` no longer trigger false offset reviews; TMDB TV and movie searches honor the configured locale; valid `Movie` and CJK movie terms are preserved.
- **CI and release safety:** adds hermetic runtime, Chromium/WebKit, and real-qBittorrent E2E lanes. Release classification now depends only on event/ref/tag metadata, and stable tags must point to `main`.

## 3.3.4-beta.2 — Safe revision replacement preview

This beta fixes revision conflicts such as an unmarked V1 episode being followed
by a matching `V2` release (#1078). The default `hold` policy keeps both
downloads and records a visible conflict instead of retrying the same rename
forever. Users may opt into the global `replace` policy to replace the older
revision automatically.

Automatic replacement is deliberately strict: Bangumi ID, media type,
season/episode, subtitle group, and resolution must all match, and the incoming
revision must be higher. The first preview only handles two single-file tasks;
collections, incomplete identities, multiple owners, and non-upgrades remain on
hold. qBittorrent and aria2 use a durable three-stage saga—stage the old file,
promote the new file, then remove the old task—with restart recovery and safe
rollback when the incoming task disappears.

The WebUI adds the global policy selector and conflict notifications. A new
conflict API supports listing and retrying held ordinary renames. Migrations
v23–v24 add the durable operation journal and aria2 filesystem intent, and the
regression suite covers concurrent claims, crash recovery, collection
protection, both download backends, and V1/V2 identity matching.

## 3.3.4-beta.1 — Multi-user authentication safety preview

This beta intentionally ships the authentication refactor before the next
stable patch. It adds first-run administrator bootstrap, multi-user session
management, and hashed API/MCP tokens whose plaintext is shown only once.
Password changes, account disablement, logout, and session rotation revoke the
right sessions without exposing bearer credentials to browser storage or API
responses. The token reveal is also scrubbed on close, route deactivation, and
late-response races, including the mobile bottom-sheet path.

It also contains the latest issue fixes: TMDB queries honor the configured
locale for TV and movie results (#1075), versioned releases such as `06v2` are
not mistaken for offset overflows (#1072), movie words are preserved in movie
titles, and release classification no longer derives versions from PR metadata
(#1065).

The refactor is guarded by isolated runtime, Chromium, WebKit, and real
qBittorrent E2E lanes. They exercise fresh setup, cookie-only refresh, session
revocation, one-time token handling, restart persistence, Windows paths, TMDB
language changes, offset review, mobile editing, and the complete RSS → real
qB download → hash verification → rename → delete flow.

## Highlights

- **In-app updates** *(new in beta.2)* — check, apply, and roll back updates from the Log page. Bundles are sha256-checked and ed25519-signed (unsigned releases are rejected, and the signature is re-verified at every boot), the database is snapshotted before promotion, and dependencies sync at apply time as a non-root user. Requires the container to run with `restart: unless-stopped` so it can restart itself.
- **Multi-provider LLM parser** *(new in beta.2)* — OpenAI-compatible endpoints (DeepSeek, Ollama, LM Studio, OpenRouter, …), Anthropic Claude, and Google Gemini, with a selectable mode: `fallback` (regex first, LLM rescues failures — default) or `primary` (LLM first). Calls get timeouts, caching, a concurrency cap, and a failure breaker, and route through the app proxy.
- **Universal title parser Preview** — Parser settings can now switch between the frozen Classic tokenizer and the new candidate/resolver tokenizer. Classic remains the default for new and upgraded installations; Preview is strictly opt-in, recognizes episode ranges and mixed TV/OVA/movie collections, and never silently falls back to Classic.
- **aria2 is now a first-class backend** — real add/query/rename/manage support with honest duplicate detection (reconciled against aria2's live state), collision-safe filesystem renames, and offset resolution via a persisted gid↔bangumi mapping. Previously aria2 could only add torrents; organization silently did nothing.
- **Movies / OVA / Specials** — the parser recognizes 剧场版/劇場版/电影版/Movie and OVA/OAD/SP/Special tokens (`episode_type`); movies are organized as flat `Title (Year)` folders with TMDB `search/movie` fallback, specials go to Season 0. Multi-file movie torrents keep distinct filenames (largest file gets the clean name).
- **Per-bangumi release preference** — set a preferred subtitle group and/or resolution per series; when multiple groups release the same episode, only the best match is downloaded instead of all of them.
- **Notifications beyond "new episode"** — typed events for RSS feed failures (on state change, not every tick), download-add failures, and offset needs-review; `{{title}}`-style message templates now work for every provider, not just webhook.
- **Offset suggestions you can apply** — season/episode offset mismatches are detected from real parsed episodes and applied with one call (`POST /api/v1/bangumi/apply-offset/{id}`, single or bulk).
- **SSE-driven WebUI** — status, downloader, and log views subscribe to `/api/v1/events/stream` instead of three polling loops; a dead downloader can no longer freeze the stream (bounded fetch with explicit degraded payload).

## Backend — Architecture

The backend went through a modernization refactor (REST API behavior unchanged):

- Database layer fully asynchronous: repositories and `Database` on `sqlite+aiosqlite` (WAL + busy_timeout); no synchronous DB calls on the event loop
- The `Program` god object replaced by a lifespan `AppContext` composition root with a generic `PeriodicTask`/`Scheduler`; startup is awaited and a failed migration aborts boot explicitly
- Composition over inheritance throughout (`RSSEngine`/`TorrentManager`/`Renamer`/… take constructor-injected dependencies)
- Table-driven migrations (`database/migrations.py`) with `already_applied` guards; old databases upgrade identically
- `Downloader` Protocol with capability flags; qBittorrent login session reused across operations with automatic re-auth on 401/403 (#1039, #900)
- Config changes uniformly through `AppContext.reload_settings()` — HTTP client, notifier, scheduler, and parser caches all reset consistently

## Backend — Features

- Security config model: login IP allowlist, MCP CIDR allowlist + Bearer Token dual authentication, `Authorization: Bearer` support on auth endpoints
- Manual air-weekday API with calendar-refresh lock (`PATCH /api/v1/bangumi/{id}/weekday`, migration v9)
- Configurable TMDB / bgm.tv API base URLs for users behind restrictive networks (#1040, #1042)
- Per-provider parser choice for custom search providers; the OpenAI parser now rescues titles the regex parser fails on instead of replacing it entirely
- Unauthenticated `GET /health` liveness endpoint (`{status, version, db_ok}`) and a Docker `HEALTHCHECK`
- Auth stack migrated from unmaintained `python-jose`/`passlib` (CVE-2024-33663, CVE-2024-33664) to PyJWT + bcrypt — existing passwords, including >72-byte ones, keep working

## Backend — Fixes

- Failed torrent adds now actually retry on the next RSS tick; "already added" duplicates no longer emit failure notifications — and downloader clients now report add outcomes honestly (a transport failure can no longer be mistaken for a duplicate)
- qBittorrent rename verification no longer reports success without seeing the new filename (#754, #749)
- Lifecycle transitions (start/stop/restart/reload) serialized behind a lock; the setup wizard now starts the background loops on completion
- Filter-rejected torrents no longer pollute offset detection
- Season offset can no longer accidentally move regular episodes into Season 0 (Plex/Jellyfin Specials); only true specials land there
- aria2: stale duplicate-tracking rows are reconciled when downloads are removed outside AutoBangumi; metadata-fetching magnets no longer crash the downloader list; renames refuse to overwrite existing files
- qBittorrent SSL: self-signed certificates no longer break the connection (#923)
- Destructive API endpoints converted from GET to POST (CSRF hardening)
- OpenAI parsing no longer blocks the event loop (`AsyncOpenAI`)

## Backend — Performance

- Title parser ~16% faster (all static regex precompiled)
- Renamer fallback lookup batched: 201 → 2 queries at 200 torrents (~11×)
- Notification dispatch parallelized across items (with the underlying HTTP-context race fixed first)
